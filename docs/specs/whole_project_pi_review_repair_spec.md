# Whole-Project PI-Review Repair Spec

Date: 2026-06-22

## 1. Goal

Make the repository PI-review-first, scientifically defensible, and claim-gated by tightening public terminology, normalizing claim statuses, regenerating stale dynamic exports, and preserving the motion/confound and DOI/archive blockers as first-class public facts.

## 2. Non-Goals

- Do not close the motion/confound gate without subject/run FD, DVARS, censoring/outlier, and confound-regression evidence.
- Do not run large downloads, run-02/music extraction, new PET/structural analyses, or external dataset expansion.
- Do not claim receptor-level proof, subjective-experience simulation, clinical validity, or completed thesis status.
- Do not hand-edit `_site/`; regenerate it.
- Do not deploy, push, create a release, or mint a DOI in this pass.

## 3. Audiences

- PI/supervisor/committee: needs the project, current proxy result, blocker, and reviewer ask in under 30 seconds.
- Scientific reviewer: needs claim status, evidence source, caveat, and next check.
- Technical auditor: needs source artifacts, build/test commands, and generated artifact provenance.
- Future maintainer: needs stable vocabulary and route/source-of-truth boundaries.

## 4. Route Map

- `/`: sparse public router generated by `scripts/build_github_pages.py`.
- `/pi-review/`: canonical first-read summary copied from `OPEN_ME_FIRST.html`.
- `/pi-review/pages/decision-gates.html`: blocker and review decision route.
- `/pi-review/pages/claim-ledger.html`: claim-to-evidence status route.
- `/pi-review/pages/figure-atlas.html`: curated figure route with claim/status/source semantics.
- `/pi-review/pages/evidence-and-calculations.html`: evidence ledger plus numeric details.
- `/dashboard/`: technical evidence console and deep audit surface.

## 5. Claim-Status Grammar

Allowed public statuses:

- `implemented`
- `proxy-supported`
- `mixed`
- `unsupported`
- `blocked`
- `future`

Raw artifact statuses may still exist in machine-readable JSON when they encode implementation state, but public claim cards, claim ladders, and PI-facing tables must display the controlled vocabulary.

## 6. Evidence-Gate Model

- C can be `proxy-supported`, not thesis-complete, until motion/confound and atlas gates pass.
- E1 lower transition/control-energy proxy can be `proxy-supported` if current artifacts support it.
- E2 receptor-specific placement is `unsupported` or `future` until structural graph, PET 5-HT2A, and spatial-null gates promote it.
- B as main control-theory result is `unsupported`; B as a negative-control baseline is `implemented`.
- Motion/confound gate remains `blocked` until required subject/run confound artifacts exist.
- GitHub release and Zenodo DOI/archive state are separate gates.

## 9. Risk Assessment

- Regeneration can touch many tracked result artifacts; review diffs before staging.
- Build script has side effects across `results/`, publication package outputs, and `_site/`.
- Public wording fixes can break tests that asserted old labels; update tests only where the expected public claim state changed.
- Over-aggressive search/replace could damage code identifiers and schemas; preserve `dynamic_mechanism` and `mechanism_ranking` keys where they are API/schema names.

## 10. Rollback Plan

Revert source/doc edits and rerun the project generators from the previous commit if regenerated artifacts are noisy or scientifically inconsistent. Do not recover by hand-editing `_site/` or partial generated copies.

- Dashboard displays controlled status labels for public claim cards and tables.
- C wording is proxy-supported and motion-gated.
